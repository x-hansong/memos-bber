# Selection Button Hover Tag Picker

## Problem Frame
当前“选中文字后出现的存到 MEMOS 悬浮按钮”只有一键保存路径，适合快速收集，但不适合“这次想手动补一个标签再保存”的场景。用户已经有现成的候选标签配置，但这套能力只在 popup 或自动打标签流程里可用，没有进入网页内的快捷保存入口。

这次要做的是一个不打断当前快捷性的增强能力：默认点击仍然一键保存；只有当用户主动在按钮上持续悬浮一段时间时，才进入“手动选 1 个标签后再保存”的展开态。

## Requirements
- R1. 选区悬浮按钮默认行为保持不变：用户直接点击“存到 MEMOS”时，仍按当前流程立即保存，不要求先选标签。
- R2. 当用户在“存到 MEMOS”按钮上持续悬浮达到配置的等待时长后，按钮进入展开态，允许用户手动选择标签后再保存。
- R3. 等待期间需要有轻量的倒计时或进度提示，让用户明确知道“继续悬浮将进入标签选择模式”。
- R4. 展开态中的可选标签范围只复用现有候选标签配置，不新增另一套标签来源，不从最近 memo 动态抓取标签。
- R5. 展开态中用户最多只能手动选择 1 个标签；这次范围不支持多选。
- R6. 选中标签后，用户可以完成保存，最终内容按现有快速保存链路写入 memo，并把所选标签作为本次保存附加标签。
- R7. 长悬浮触发时长应为用户可配置项，允许输入任意秒数，但需要限制最小值和最大值，避免极端配置。
- R8. 用户可以关闭该功能；关闭后恢复为当前行为，即悬浮按钮只支持一键保存，不显示倒计时，也不会进入标签选择展开态。

## Success Criteria
- 保留现有“选区后一键保存”的速度与路径，不强迫所有保存进入二段式交互。
- 用户能在网页内直接完成“补选一个标签再保存”，不需要切换到 popup。
- 功能开启时具备足够可发现性；功能关闭时不残留额外提示或异常状态。
- 新能力不引入第二套标签管理来源，保持配置和心智简单。

## Scope Boundaries
- 不修改 popup 现有标签列表、自动打标签、默认标签等其他保存入口的交互。
- 不支持手动创建新标签，只能从现有候选标签中选。
- 不支持多标签选择。
- 不把最近 memo 中提取的标签作为这次功能的候选来源。
- 不改变当前选区内容提取、Memos 请求结构、权限模型或保存成功/失败提示的基本语义。

## Key Decisions
- 默认点击仍一键保存：避免把快捷入口变成重交互入口。
- “长悬浮展开”而不是弹独立浮层或跳转 popup：交互连续性最好，最符合网页内快捷动作场景。
- 标签来源只复用现有候选标签配置：避免同一功能出现两套标签来源和维护入口。
- 只允许手动选 1 个标签：与当前自动打标签“选一个最合适标签”的心智一致，也能控制展开态复杂度。
- 等待时长做成可配置，且支持关闭：把这个能力从隐藏彩蛋升级为可调增强能力，兼顾不同用户耐受度。

## Dependencies / Assumptions
- 已有候选标签配置在功能开启时可被复用，且为空时应有可预期的降级表现。
- 当前选区悬浮按钮仍由内容脚本统一控制，因此展开态和倒计时提示可以沿用同一注入入口承载。

## Outstanding Questions

### Deferred to Planning
- [Affects R3][Technical] 倒计时提示应采用数字倒计时、进度条，还是文案加视觉进度的轻量组合，由规划阶段结合现有按钮样式决定。
- [Affects R7][Technical] 等待时长的默认值、最小值、最大值需要结合现有设置页密度与使用节奏选一个合适区间。
- [Affects R4][Needs research] 当候选标签配置为空但功能开启时，展开态应该直接不出现、显示空态，还是回退到普通一键保存，需要在代码结构和体验成本之间做最终取舍。
